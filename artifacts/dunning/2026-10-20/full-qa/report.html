Corrections made during testing

  1. Preceding letter reference: newly generated later-letter PDFs carry the immediate prior reference even when custom wording omits its merge field. A regression test checks actual PDF text streams. Already issued bytes remain frozen.
  2. Header contrast: scoped styling keeps Document Setup and invoice-participation headings readable instead of inheriting a purple background with dark text.

Remaining work and test limits

  • Reports complete: the live dataset replaces the old nine-column placeholder in the existing selector, results and XLSX flow. Integration handoff remains in this chat; no message was sent to the Reports chat.
  • Non-Latin documents: add appropriate PDF font/shaping support and repeat Hindi and other intended-language visual/text checks before claiming multilingual support.
  • Pending business decisions: retry cap, scheduling after a pause with missed dates, and the restart stage after removing an exclusion remain pending team confirmation.
  • Prototype boundary: actual daily processing was driven through an artifact-only test harness using the real browser-persisted engine, template data and PDF renderer. There is no production background scheduler or real mail-provider delivery in this prototype.
  • Download boundary: the in-app browser did not expose a native download completion receipt. Stored/generated bytes were saved independently and verified with a PDF reader; the operating-system save-file interaction remains unverified.
  • Accessibility: setup-header contrast was corrected. This test is not a full WCAG certification; keyboard/screen-reader naming and narrow/mobile layouts still need a separate accessibility pass.
